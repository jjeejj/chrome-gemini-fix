# Chrome「Gemini in Chrome 不可用」修复方案

> 适用：macOS + Chrome 156.0.8078.48（实测版本）
> 现象：侧边栏显示「Gemini in Chrome isn't available — Gemini in Chrome is expanding to different locations but isn't available everywhere」，带定位图标。
> 整理时间：2026-10-24

---

## 一、结论先行

Chrome 的地域门禁由**两个本地字段**决定，而 Chrome 每次启动后都会从 Google 的 variations seed 把它们改回中国状态。所以必须同时满足两个条件：

| 条件 | 做法 | 谁提供 |
|---|---|---|
| 1. 固定字段值 | `chflags uchg` 锁住 `Local State`，让 Chrome 写不进去 | `glic apply`（一次性） |
| 2. 启动时传参 | `--variations-override-country=us` | 启动图标 / `glic launch` |

**缺一不可**（实测对照）：

| 组合 | 结果 |
|---|---|
| 只锁文件、不带开关 | `previously_not_allowed` 20 秒内翻回 `true`，立刻失效 |
| 只带开关、不锁文件 | `variations_country` 被覆写回 `cn`，几分钟内失效 |
| 锁文件 + 带开关 | 稳定可用 |

---

## 二、根本原因

### 2.1 门禁读的是本地状态

Chrome 内部把 Gemini 侧边栏叫做 **Glic**（`chrome/browser/glic/`）。判定逻辑读两个 pref：

```
Local State → variations_country                      必须 = "us"
Local State → profile.info_cache.*.is_glic_eligible   必须 = true
```

`Local State` 完整路径：

```
~/Library/Application Support/Google/Chrome/Local State
```

提示文案本身就在本地资源里（`Resources/en.lproj/locale.pak`），不是远程页面渲染的。

### 2.2 Chrome 会自己改回来

即使出口 IP 在美国（实测 `38.145.220.153 / loc=US`），Chrome 启动后会拉一次 variations seed，并把 `variations_country` 写成 `cn`、把 `is_glic_eligible` 写成 `false`。

这就是「改完配置重启又不行」的原因——本方案的核心不是改值，而是**让 Chrome 改不回去**。

### 2.3 还有一个隐藏开关

Chrome 正式版支持未公开的启动参数：

```
--variations-override-country=us
```

（从 `Google Chrome Framework` 二进制里 `strings` 提取，同组还有 `variations-server-url`、`variations-seed-fetch-interval` 等。）

它能强制 variations 国家码为 `us`。**但只在启动瞬间有效**，对已运行的 Chrome 实例完全无效，也没法写进任何配置文件。

### 2.4 辅助观察指标

`Default/Preferences`（**未被锁定**）里的 glic 状态，是判断「当前到底好不好使」的关键：

| 字段 | 正常值 | 说明 |
|---|---|---|
| `glic.previously_not_allowed` | `false` / 不存在 | 变成 `true` 就是被拒绝了 |
| `glic.profile_enablement.last_ready_state` | `2` | `2` = 就绪；`5` = 未就绪。从启动到变成 `2` 约需 **60 秒** |

> 只看 `variations_country = us` 会被骗——文件里是 `us`，Chrome 内存里可能已经是 `cn`。

## 三、已落地的两个产物

### 3.1 命令行工具 `glic`

```bash
~/.local/bin/glic          # 单文件 Python 脚本，仅用标准库
```

| 命令 | 作用 |
|---|---|
| `glic` / `glic status` | 查看状态（Chrome 开着也能跑） |
| `glic apply`（= `glic on`） | 退出 Chrome → 修复字段 → 锁定 → 带开关启动 |
| `glic unlock`（= `glic off`） | 解除锁定（放弃修复时用） |
| `glic launch` | 带开关启动 Chrome（Chrome 必须先是关着的） |
| `glic -h` | 帮助 |

`~/.local/bin` 已在 PATH 中（`.zshenv` / `.zprofile` 都有），新开终端即可用；当前终端需 `hash -r`。

### 3.2 启动图标

```
~/Applications/Chrome (Gemini).app
```

内部就一段 shell：

```sh
# 1. 防呆：Chrome 已运行则弹框退出（参数对已运行实例无效）
if pgrep -f "MacOS/Google Chrome" >/dev/null; then
  osascript -e 'display dialog "Chrome 已经在运行，启动开关传不进去..."'
  exit 0
fi
# 2. 带参数 exec，让 Chrome 成为 launchd 托管的进程
exec "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
     --variations-override-country=us
```

图标从 Chrome 原版的 `Assets.car` + `AppIcon` 复用，视觉与原版一致。

> **建议**：把它拖到 Dock，替换掉原来的 Chrome 图标，日常点它就等于点 Chrome。

## 四、日常使用

### 4.1 启动 Chrome

**只能用下面三种方式之一**，效果等价：

1. 双击 `Chrome (Gemini).app`
2. 终端 `glic launch`
3. 终端 `glic apply`（会连修复一起做）

❌ **不要直接点原版 Chrome**（Dock 里那个、Launchpad 里那个、Spotlight 搜出来的）——不带开关，会失效。

### 4.2 自查

```bash
glic
```

两行都正常才是好的：

```
override 开关      : 已生效
previously_not_allowed: False
```

看到 `override 开关: 未生效` → 说明是用原版图标启动的 → 退出 Chrome，`glic launch`。

### 4.3 出问题时

```bash
glic apply
```

一条命令重建：清字段 → 锁文件 → 带开关启动。

## 五、代价与限制

锁定期间 Chrome 无法写 `Local State`，因此：

| 影响 | 说明 |
|---|---|
| ⚠️ `chrome://flags` 改动不保存 | `enabled_labs_experiments` 在这个文件里 |
| ⚠️ 全局 UI 状态不持久化 | 上次使用的 profile、崩溃恢复信息等 |
| ✅ 书签 / 历史 / 密码 / Cookie / 扩展 | 全部不受影响（在 profile 目录） |

### 要改 `chrome://flags` 时

```bash
glic unlock                 # 解锁 + 退出 Chrome
# 打开 Chrome（此时用原版图标即可），改 flags，Cmd+Q
glic apply                  # 重新修复 + 锁定 + 带开关启动
```

`apply` 只清 `variations_*` 和几个资格字段，**不会动你已经设好的 flags**。

### Chrome 大版本更新后

更新可能重置状态，直接跑一次 `glic apply` 即可（会自动写入新版本号）。

## 六、回滚

```bash
glic unlock                 # 解除锁定（Chrome 会被先退出）
```

若想彻底清理：

```bash
rm -rf "$HOME/Applications/Chrome (Gemini).app"
rm -f  "$HOME/.local/bin/glic"
```

已改动的字段（`countryid_at_install` 等）会保留但不再生效；需要完全还原可从备份恢复：

```
~/Library/Application Support/Google/Chrome/Local State.bak.*
~/Library/Application Support/Google/Chrome/Default/Preferences.bak.*
```

> 备份会随每次 `apply` 增加，确认稳定后可自行删除旧的。

## 七、原理附录：为什么是 `chflags uchg` 而不是 `chmod 444`

Chrome 保存配置的方式是「写临时文件 → `rename` 覆盖」。实测对照：

```
--- chmod 444 ---
  被成功覆盖，内容=new            ← 完全挡不住

--- chflags uchg ---
  EPERM: operation not permitted, rename
  追加写入也被挡住 ✔
  删除也被挡住 ✔
```

`chmod` 只管文件权限，管不了目录项，rename 照样能换掉；`uchg` 是 inode 级标志，`open/write`、`unlink`、`rename` 全被内核拒绝。

| 项 | 说明 |
|---|---|
| 查看 | `ls -lO 文件`，第 5 列显示 `uchg` |
| 解除 | `chflags nouchg 文件` |
| 权限 | 只有文件 owner 能设/解，不需要 sudo |
| 重启后 | 依然有效（标志写在 inode 上） |
| GUI 对应 | Finder「显示简介」里的「已锁定」勾选框 |

## 八、排查过程中的坑（备查）

| 坑 | 说明 |
|---|---|
| `ipinfo.io` / `ipapi.co` 显示 CN | 这些域名在 Clash 分流规则里走 DIRECT，不代表 VPN 失效。测海外出口用 `https://www.cloudflare.com/cdn-cgi/trace` 看 `loc=` |
| `open -a ... --args` 不可靠 | 对已运行的 Chrome 完全无效；即使未运行也可能不传参。可靠做法是直接 exec 二进制 |
| 搜索 Chrome UI 文案 | 别用 `find -maxdepth` + `strings`，会漏 `Resources/<lang>.lproj/locale.pak`。用 `grep -ral --binary-files=text "文案" "/Applications/Google Chrome.app"` |
| `chrome://glic-internals` | 正式版未注册该 host，返回 `ERR_INVALID_URL`；`chrome://glic` 单独打开是空白（WebUI 只服务侧边栏宿主） |
| 用 `osascript quit` 关 Chrome | 会被「确认退出」对话框卡住；`kill -TERM <主进程>` 反而干净 |
| 系统代理 | **不需要**。TUN 模式已在网络层接管，实测 `gemini.google.com` / `geminiweb-pa.googleapis.com` / `clients2.google.com` 全部走代理，且本机无公网 IPv6，不存在绕过 TUN 的泄漏 |
| `chrome://flags` 里的 `#glic-side-panel` | Chrome 156 已移除，老教程才提。只需 `#glic` |

---

## 九、一句话总结

> 把 Chrome 的全局配置文件设成「已锁定」，防止它把国家码改回 `cn`；再用一个带 `--variations-override-country=us` 的启动器启动。两件事配合，侧边栏才稳定可用。
